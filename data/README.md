# Data Directory

Place benchmark `.mat` files in this directory. Active scripts default to this
path and also accept `--data-dir` for alternate locations.

Two minimal, headless data-generation scripts are included:

- `Burgers.m`: generates `BurgersOSG_train.mat` and `BurgersOSG_test.mat`.
- `convection_diffusion.m`: generates `train_data.mat` and `test_data.mat` for
  the 2D advection--diffusion benchmark.

The scripts only generate `.mat` files and run shape checks. They do not create
figures or diagnostic images.

The Navier--Stokes files are derived from DUE benchmark data and are not
generated by scripts in this repository.

The repository `.gitignore` keeps `*.mat` files out of normal git commits.
Some files exceed GitHub's regular 100 MB file limit. Do not commit `.mat`
files to the normal git repository. If distributing data through GitHub, use Git
LFS or a GitHub Release asset after confirming that dataset redistribution
permission is clear.

The Navier--Stokes files are derived from the DUE benchmark data used by our
group. Keep the DUE attribution in `NOTICE` and `docs/third_party_attribution.md`
when redistributing these files.

## Regenerating Scripted Data

Run these commands from MATLAB with this directory as the working directory, or
open the scripts directly:

```matlab
Burgers
convection_diffusion
```

Both scripts write their `.mat` outputs into this directory and stop with an
assertion error if the generated arrays do not match the expected benchmark
format.

Both scripted benchmarks use endpoint-excluded periodic grids. For example, the
advection--diffusion grid uses `x = -pi + (0:N-1) * (2*pi/N)` rather than
`linspace(-pi, pi, N)`, so the coordinate metadata matches the periodic FFT
grid.

Expected variable names:

- Training files include `coordinates`, `dt`, and `trajectories`.
- Test files include `dt` and `trajectories`; Burgers test also includes
  `coordinates`.

The stored checksums above document the local `.mat` files currently used for
smoke tests. If the generation scripts are edited or rerun under a different
MATLAB version, regenerate the checksums before publishing data artifacts.

## Copying Data to a Training Machine

After generating the scripted data locally, copy the `.mat` files to the
`data/` directory of the repository checkout used for training:

```text
<repo>/data/
```

Recommended files to copy after regenerating local data:

```text
BurgersOSG_train.mat
BurgersOSG_test.mat
train_data.mat
test_data.mat
```

If the Navier--Stokes benchmark files already exist on the server and have not
changed, leave them in place:

```text
VorticityOSG_train.mat
VorticityOSG_test.mat
```
